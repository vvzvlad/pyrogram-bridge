# Pyrogram Bridge

[English](README.md) · [Русский](README.ru.md)

Превращает Telegram-каналы в RSS-ленты. Мост входит в Telegram как обычный пользовательский
аккаунт (MTProto, через [Kurigram](https://github.com/KurimuzonAkuma/pyrogram) — форк
Pyrogram), читает историю канала и отдаёт её по HTTP в виде RSS, HTML-страницы или JSON — с
медиа, альбомами, ответами и реакциями, и с фильтрами, которые выкидывают посты, которые вы
читать не хотите.

Он читает всё, что может прочитать этот аккаунт: публичные каналы — по username, закрытые
каналы, на которые аккаунт подписан, — по числовому id. Ничего сверхъестественного — это
просто ещё один клиент Telegram.

В паре с ним работает [miniflux-tg-add-bot](https://github.com/vvzvlad/miniflux-tg-add-bot):
пересылаешь боту пост, он подписывает Miniflux на ленту канала из моста, а потом кнопками
переключает фильтры этой ленты.

---

## Возможности

- **RSS-лента на каждый канал** — `/rss/<канал>`; те же посты можно получить и одной
  HTML-страницей.
- **Отдельные посты** в HTML или JSON — `/html/<канал>/<id>`, `/json/<канал>/<id>`.
- **Медиа через мост** — фото, видео и файлы скачиваются из Telegram, кэшируются в томе с
  данными и отдаются по подписанным ссылкам, так что RSS-читалке доступ к Telegram не нужен.
- **Альбом — одна запись**; по желанию склеиваются и посты, опубликованные с разницей в
  несколько секунд.
- **Фильтрация постов** — выкидывайте посты по встроенным флагам (реклама, репосты, ссылки на
  чужие каналы, стримы, мемы с клоунами в реакциях, …) и по своему регулярному выражению —
  для каждой ленты отдельно, прямо в её URL. См. [Фильтрация постов](#фильтрация-постов).
- **Полноценный рендер** — ответы с цитатой исходного поста, опросы, превью ссылок, Rich
  Messages, реакции, просмотры и ссылки обратно в Telegram.
- **Бережно к Telegram** — сведения о канале и история кэшируются, живые запросы идут с
  ограничением темпа; FloodWait превращается в HTTP 429 с `Retry-After`; на условные запросы
  с `ETag`/`Last-Modified` лента отвечает 304.
- **Самовосстановление** — встроенный watchdog перезапускает зависшую сессию Telegram, а
  `/ping` обслуживает healthcheck контейнера.

## Быстрый старт (Docker)

1. Получите `api_id` и `api_hash`: войдите на <https://my.telegram.org/apps> →
   *API development tools* → создайте приложение.

2. Создайте `docker-compose.yml` (или стек в Portainer):

   ```yaml
   volumes:
     pyrogram_bridge:

   services:
     pyrogram_bridge:
       image: gitea.vvzvlad.xyz/projects/pyrogram-bridge:latest
       container_name: pyrogram-bridge
       environment:
         TG_API_ID: 12345678
         TG_API_HASH: 0123456789abcdef0123456789abcdef
         PYROGRAM_BRIDGE_URL: https://pgbridge.example.com
         API_PORT: 80
         TOKEN: change-me
         TZ: Europe/Moscow
       restart: always
       volumes:
         - pyrogram_bridge:/app/data
       labels:
         traefik.enable: "true"
         traefik.http.routers.pgbridge.rule: Host(`pgbridge.example.com`)
         traefik.http.services.pgbridge.loadBalancer.server.port: 80
         traefik.http.routers.pgbridge.entrypoints: websecure
         traefik.http.routers.pgbridge.tls: true
   ```

   Более полный пример — [`docker-compose.yml`](docker-compose.yml) в репозитории: все
   необязательные переменные с комментариями, ротация логов и healthcheck.

3. Один раз войдите в Telegram в интерактивном режиме — **до** того, как запускать мост
   по-настоящему. Без сессии мост при старте спрашивает номер телефона; у контейнера, работающего
   в фоне, нет терминала, чтобы спросить, поэтому он падает на старте и уходит в бесконечный
   перезапуск.

   С Docker Compose — из каталога с compose-файлом:

   ```bash
   docker compose run --rm pyrogram_bridge
   ```

   С Portainer или голым Docker: разверните стек, остановите его и запустите разовый контейнер
   на томе стека. Compose и Portainer добавляют к имени тома имя проекта или стека, так что
   настоящее имя смотрите в `docker volume ls`:

   ```bash
   docker run --rm -it -v <стек>_pyrogram_bridge:/app/data \
     -e TG_API_ID=12345678 -e TG_API_HASH=0123456789abcdef0123456789abcdef \
     gitea.vvzvlad.xyz/projects/pyrogram-bridge:latest
   ```

   Введите номер телефона, код, который пришлёт Telegram, и, если включена двухэтапная
   проверка, пароль:

   ```text
   Enter phone number or bot token: +7 900 000 00 00
   Is "+7 900 000 00 00" correct? (y/N): y
   The confirmation code has been sent via Telegram app
   Enter confirmation code: 12345
   The two-step verification is enabled and a password is required
   Password hint: None
   Enter password (empty to recover): ********
   ```

   Дождитесь строки `INFO:     Application startup complete.` и остановите процесс по Ctrl+C.

4. Запустите мост: `docker compose up -d` (или запустите стек).

Сессия сохраняется в файл `pyro_bridge.session` в томе с данными (`/app/data` внутри
контейнера). Этот файл *и есть* залогиненный аккаунт: берегите его и никому не отдавайте.

Проверка: `curl https://pgbridge.example.com/rss/DragorWW_space/change-me`.

## Использование

### Эндпоинты

| URL | Что возвращает |
| --- | --- |
| `/rss/<канал>` | RSS-ленту канала |
| `/rss/<канал>?output_type=html` | те же посты одной HTML-страницей — удобно проверять фильтры в браузере |
| `/html/<канал>/<id_поста>` | один пост в HTML; пост из альбома показывается вместе со всем альбомом |
| `/json/<канал>/<id_поста>` | одно сообщение в JSON: текст, готовый HTML, флаги, дата, автор, просмотры, реакции, превью ссылки |
| `/flags` | список флагов, которые ставит мост, в JSON (см. [Фильтрация постов](#фильтрация-постов)) |
| `/ping`, `/health` | живость и состояние (см. [Мониторинг](#мониторинг)) |

`<канал>` — публичный username без `@` (`DragorWW_space`) или числовой id канала
(`-1002069358234`). По id открываются закрытые каналы — аккаунт моста должен быть на них
подписан. Чтобы узнать id, перешлите пост из канала боту
[@userinfobot](https://t.me/userinfobot) — он ответит `Id: -100…`.
[miniflux-tg-add-bot](https://github.com/vvzvlad/miniflux-tg-add-bot) делает это сам.

Страницы отдельных постов принимают `?debug=true`: тогда на странице показываются ещё
заголовок поста и сырое сообщение Telegram.

### Параметры ленты

Все они передаются в query-строке и комбинируются друг с другом:

| Параметр | По умолчанию | Значение |
| --- | --- | --- |
| `limit` | `50` | Максимум записей, 1–200. Часто их выходит меньше — см. [ниже](#почему-в-ленте-меньше-записей-чем-limit). |
| `exclude_flags` | — | Флаги через запятую; посты с любым из них выкидываются. См. [Фильтрация постов](#фильтрация-постов). |
| `exclude_text` | — | Регулярное выражение; посты, текст которых ему соответствует, выкидываются. |
| `merge_seconds` | `5` | Окно склейки по времени; действует только при `TIME_BASED_MERGE=true`. См. [Склейка постов](#склейка-постов). |
| `output_type` | `rss` | `rss` или `html`. |
| `token` | — | Токен доступа — вместо последнего сегмента пути `/<TOKEN>`. |

```text
https://pgbridge.example.com/rss/DragorWW_space?limit=30&exclude_flags=advert,fwd
https://pgbridge.example.com/rss/DragorWW_space/change-me?exclude_text=розыгрыш|giveaway
https://pgbridge.example.com/rss/-1002069358234?merge_seconds=10
```

### Таймауты

Лента, которой ещё нет в кэше, может собираться долго: мост шлёт в Telegram по одному запросу
за раз, с паузой между ними, а сверху ещё скачиваются медиа. Поставьте читалке щедрый
HTTP-таймаут — в Miniflux это `HTTP_CLIENT_TIMEOUT=200`. Если Telegram отвечает FloodWait,
мост не зависает, а возвращает `429 Too Many Requests` с заголовком `Retry-After` (не больше
190 секунд).

## Фильтрация постов

Фильтры живут в URL каждой ленты, так что один и тот же канал можно в одном месте читать
целиком, а в другом — почищенным. Фильтров два, и они складываются: пост выкидывается, если
подходит под **любой** из них.

### По флагам — `exclude_flags`

При рендере мост помечает каждый пост флагами, описывающими его содержимое. `exclude_flags`
принимает их список через запятую, и пост, у которого есть **хотя бы один** из перечисленных
флагов, выкидывается:

```text
/rss/DragorWW_space?exclude_flags=advert,fwd,clownpoo
```

| Флаг | Пост… |
| --- | --- |
| `advert` | содержит рекламные маркеры: `#реклама`, `#промо`, «партнерский пост», «по промокоду», пометку `erid` и тому подобное |
| `fwd` | переслан из другого канала или от пользователя |
| `foreign_channel` | ссылается на другой публичный канал (`t.me/othername` или буст-ссылка другого канала); ссылки на сам канал не считаются |
| `hid_channel` | содержит инвайт в закрытый канал (`t.me/+…`) |
| `link` | содержит внешнюю `http(s)`-ссылку; ссылки на `t.me` не считаются |
| `only_link` | состоит только из одной внешней ссылки или только из превью ссылки (получает `only_link` вместо `link`) |
| `mention` | упоминает `@username` |
| `donat` | просит донатов: «донат…», `pay.cloudtips.ru`, ссылки `t.me/boost/…` |
| `paywall` | упоминает платные площадки: Boosty/Бусти, Sponsr, Дзен.Премиум |
| `stream` | анонсирует стрим или вебинар: «стрим…», livestream, «вебинар…», «онлайн-лекция» |
| `clownpoo` | набрал не меньше 30 реакций 🤡 или не меньше 30 реакций 💩 |
| `video` | видео, GIF, кружок или live photo, а текста не больше 200 символов |
| `audio` | аудиофайл или голосовое, а текста не больше 200 символов |
| `no_image` | без картинки и видео: только текст, файл, опрос без медиа… |
| `sticker` | стикер |
| `poll` | опрос |
| `rich` | Rich Message |
| `merged` | собран из нескольких сообщений: альбом или склейка по времени |

`/flags` возвращает актуальный список — всё из таблицы, кроме `merged`: этот флаг ставится
позже, при группировке сообщений, но в `exclude_flags` работает так же. Кнопки флагов в
miniflux-tg-add-bot строятся по этому эндпоинту.

Что важно знать:

- **Флаги описывают собственное содержимое поста.** Упоминание или ссылка внутри сообщения,
  на которое пост отвечает, не дают флагов `mention`, `link`, `hid_channel` и
  `foreign_channel`.
- **Альбом или склеенная запись получает флаги всех своих частей**, поэтому выкидывается
  целиком, если под фильтр попала любая часть.
- **`exclude_flags=all` выкидывает все посты, у которых есть хоть один флаг** — а это гораздо
  больше, чем кажется: у текстовых постов есть `no_image`, у альбомов — `merged`, так что `all`
  опустошает большинство лент. Лучше перечислить нужные флаги явно.
- **Чтобы увидеть, какие флаги получают посты**, включите `SHOW_POST_FLAGS=true`: тогда в конце
  каждой записи будут её флаги (`🏷 advert 🏷 link`). Вместе с `?output_type=html` это самый
  быстрый способ подобрать фильтр прямо в браузере.

### По тексту — `exclude_text`

`exclude_text` — регулярное выражение
([синтаксис Python](https://docs.python.org/3/library/re.html#regular-expression-syntax)),
которое без учёта регистра ищется в тексте поста — тексте сообщения или подписи к медиа; у
альбома — в текстах всех его частей. Пост, в котором выражение нашлось где угодно,
выкидывается:

```text
/rss/DragorWW_space?exclude_text=розыгрыш|giveaway
/rss/DragorWW_space?exclude_text=все.*комикс|реклам.*канал
```

Второй пример выкидывает посты, где есть «все», а где-то дальше — «комикс», и посты, где за
«реклам» следует «канал».

- **Варианты разделяются через `|`, а не через запятую.** В регулярном выражении запятая —
  обычный символ: `реклама,акция` найдёт только ровно эту строку.
- **Ищется только видимый текст** — не адреса за гиперссылками и не цитата сообщения, на
  которое пост отвечает.
- **Спецсимволы в URL нужно кодировать.** `+` пишется как `%2B` (без кодирования он
  превращается в пробел, и `\d+` молча становится «цифра и пробел»), `#` — как `%23`, `&` —
  как `%26`. Кириллицу большинство читалок кодируют сами; если ваша не умеет, подойдёт любой
  URL-кодировщик, например <https://www.urlencoder.org/>.
- **Выражение, которое не компилируется, роняет запрос ленты** с ошибкой — лента не
  возвращается молча без фильтра.

### Почему в ленте меньше записей, чем `limit`

- **Фильтры работают после `limit`.** Мост берёт `limit` самых свежих записей и только потом
  выкидывает отфильтрованные, так что после жёсткого фильтра может остаться всего несколько.
  Компенсируйте это бо́льшим `limit`.
- **Альбом занимает по сообщению на каждую картинку.** RSS-лента читает из канала
  `2 × limit` сообщений, а альбом из 10 фото расходует десять из них, поэтому на канале с
  большими альбомами изменение `limit` может почти ничего не менять. HTML-лента
  (`output_type=html`) читает ровно `limit` сообщений.

## Склейка постов

Telegram хранит альбом как отдельные сообщения — по одному на фото или видео. Мост всегда
собирает их обратно в одну запись.

Некоторые каналы вместо альбома публикуют серию отдельных сообщений — картинку, а следом
подпись к ней, длинный текст в несколько частей. При `TIME_BASED_MERGE=true` мост склеивает в
одну запись и каждое сообщение, опубликованное не позже чем через `merge_seconds` (по
умолчанию 5) после предыдущего; окно можно поменять для отдельной ленты через
`?merge_seconds=…`. Без `TIME_BASED_MERGE` этот параметр ничего не делает. Склеенные записи
получают флаг `merged`.

## Токен доступа

Кто может достучаться до моста, тот читает через него всё, что может прочитать ваш аккаунт
Telegram, — а Telegram видит всё это как активность вашего аккаунта, и рано или поздно это
заканчивается ограничениями или баном за ботоводство. Если мост доступен из интернета,
задайте `TOKEN`.

Когда `TOKEN` задан, его требуют все эндпоинты, кроме `/`, `/ping` и ссылок на медиа, —
последним сегментом пути или query-параметром:

```text
https://pgbridge.example.com/rss/DragorWW_space/change-me
https://pgbridge.example.com/rss/DragorWW_space?token=change-me&limit=30
```

Ссылкам на медиа токен не нужен: каждая несёт собственную подпись (см.
`MEDIA_SIGNING_SECRET`).

Запросы с `127.0.0.1` / `::1` проверку пропускают. Если ваш reverse proxy ходит в мост с
localhost, все запросы будут выглядеть локальными — впишите адрес прокси в
`TRUSTED_PROXIES`, и тогда реальный адрес клиента будет браться из `X-Real-IP` /
`X-Forwarded-For`.

## Настройка

Всё настраивается переменными окружения. Обязательны только `TG_API_ID` и `TG_API_HASH` —
без них мост не запустится.

### Основное

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `TG_API_ID` | — | API id Telegram с my.telegram.org. Обязательна. |
| `TG_API_HASH` | — | API hash Telegram с my.telegram.org. Обязательна. |
| `PYROGRAM_BRIDGE_URL` | — | Публичный базовый URL моста, например `https://pgbridge.example.com`. Из него строятся ссылки на медиа в лентах; без него они относительные (`/media/…`), и картинки загрузятся, только если читалка достроит их до адреса моста. |
| `TOKEN` | — | Токен доступа, см. [Токен доступа](#токен-доступа). |
| `API_PORT` | `8000` | HTTP-порт внутри контейнера. |
| `API_HOST` | `0.0.0.0` | Адрес, на котором слушать. |
| `TRUSTED_PROXIES` | — | Адреса reverse proxy через запятую, чьим `X-Real-IP` / `X-Forwarded-For` можно доверять. |
| `TZ` | `UTC` | Часовой пояс дат в постах. |
| `LOG_LEVEL` | `INFO` | Уровень логирования. |
| `DEBUG` | `false` | Печатать сырое сообщение Telegram в stdout при каждом запросе отдельного поста. |
| `SESSION_PATH` | `data` | Каталог файла сессии Telegram, относительно `/app`. |

### Содержимое ленты

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `TIME_BASED_MERGE` | `false` | Склеивать посты, опубликованные с разницей в несколько секунд, см. [Склейка постов](#склейка-постов). |
| `SHOW_POST_FLAGS` | `false` | Показывать флаги поста в конце записи. |
| `SHOW_BRIDGE_LINK` | `false` | Добавлять к каждому посту ссылку «Open in Bridge» (страница поста с `debug=true`). В ссылке есть `TOKEN`, так что его увидит каждый, кто читает ленту. |
| `REPLY_QUOTE_TRUNCATE_CHARS` | `200` | Когда пост отвечает на соседний пост того же канала, от цитаты остаётся столько видимых символов — иначе читалка показывает пост A целиком, а следом пост B со всем A внутри. `0` — цитаты не обрезаются. Ответы на другие каналы, пользователям и на старые посты не обрезаются никогда. |
| `REPLY_QUOTE_TRUNCATE_DISTANCE` | `2` | Насколько далеко друг от друга (в id сообщений) могут быть ответ и исходный пост, чтобы цитата обрезалась; 2 покрывает «ответ на пост прямо выше», даже после альбома. `0` отключает обрезку. Оба значения применяются при рендере, чистить кэш не нужно. |

### Ссылки на медиа

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `MEDIA_SIGNING_SECRET` | — | Секрет для подписи ссылок на медиа (HMAC-SHA256, ключ выводится через HKDF). Если не задан, ключ выводится из `TOKEN`, а без `TOKEN` берётся из файла-ключа, сгенерированного в томе с данными. Задайте его или `TOKEN`: файл-ключ пропадёт вместе с томом, а с ним умрут все ссылки на медиа, уже доставленные в читалки. |
| `MEDIA_ALLOW_LEGACY_DIGEST` | `true` | Принимать и ссылки, подписанные по старой схеме (SHA-1, 8 символов), чтобы выданные до обновления ссылки продолжали работать. Ставьте `false`, когда все ленты перечитаны. |
| `MEDIA_URL_TTL_DAYS` | — | Подписанный срок жизни ссылок на медиа, в днях. Не задано — срока нет, и для RSS это правильно: читалки часто подгружают медиа записи спустя дни. |

### Watchdog

Watchdog периодически проверяет, что сессия Telegram действительно жива, и перезапускает её
внутри процесса, если нет.

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `TG_WATCHDOG_ENABLED` | `true` | Включить или выключить watchdog. |
| `TG_WATCHDOG_INTERVAL` | `60` | Секунд между проверками. |
| `TG_WATCHDOG_TIMEOUT` | `10` | Таймаут одной проверки, секунды. |
| `TG_WATCHDOG_FAILURES` | `3` | Сколько проверок подряд должно провалиться до перезапуска. |
| `TG_WATCHDOG_RESTART_TIMEOUT` | `90` | Таймаут самого перезапуска, секунды. |
| `TG_WATCHDOG_HEARTBEAT_EVERY` | `30` | Писать в лог INFO-пульс каждые N успешных проверок. |
| `TG_DISCONNECT_FLAP_LIMIT` | `3` | Сколько разрывов связи за окно вызывают перезапуск. |
| `TG_DISCONNECT_FLAP_WINDOW` | `120` | Это окно, секунды. |
| `TG_PING_UNHEALTHY_AFTER` | `250` | `/ping` сообщает о проблеме, если последняя успешная проверка старше этого числа секунд. По умолчанию выводится из трёх значений выше: интервал × (провалы + 1) + таймаут. |

### Кэш и задержки

- История канала кэшируется на 6,4–8 часов (8 часов со случайным разбросом для каждого
  канала), так что новый пост может появиться в ленте с такой задержкой. Именно это держит
  частоту запросов аккаунта к Telegram низкой.
- Медиа из отрендеренных постов скачиваются в фоне и хранятся в томе с данными; файл, который
  никто не запрашивал 20 дней, удаляется.
- Ленты отдаются с `Cache-Control: private, max-age=300` и на условные запросы отвечают
  `304 Not Modified`.

## Мониторинг

- **`/ping`** — мгновенная проверка живости для healthcheck контейнера; в Telegram не ходит.
  Отвечает `200 {"status": "ok", …}`, пока сессия подключена и последняя успешная проверка
  watchdog свежая, и `503 {"status": "degraded", …}` в остальных случаях. Пример healthcheck —
  в [`docker-compose.yml`](docker-compose.yml) репозитория.
- **`/health`** (нужен токен) — обращается к Telegram и возвращает JSON с залогиненным
  аккаунтом, конфигурацией (секреты замаскированы), статистикой кэша медиа и счётчиками ошибок
  рендера.

## Обновление

Контейнер намеренно стартует от root: entrypoint сначала отдаёт том с данными (`/app/data`)
пользователю с uid 1000, а потом переключается на него и запускает сервис. Поэтому старая
установка, в томе которой остались файлы root, обновляется без ручных шагов.

Если в compose-файле задан `user: "1000:1000"` (uid пользователя `app` в образе), контейнер
стартует от этого пользователя и том не трогает. Старый том с файлами root тогда нужно один раз отдать
пользователю вручную (настоящее имя тома — в `docker volume ls`):

```bash
docker run --rm -v <стек>_pyrogram_bridge:/data busybox chown -R 1000:1000 /data
```
